# ProofLens coverage against mathlib

This is the honest answer to the question that matters: **on what fraction of
real mathematics does ProofLens say anything useful, and what would move that
number?**

It is generated by `prooflens coverage`, not written by hand. Regenerate it with:

```bash
pnpm prooflens extract --project corpus \
  --module Mathlib.Order.Monotone.Basic \
  --module Mathlib.Algebra.Order.Field.Basic \
  --module Mathlib.Analysis.SpecialFunctions.Log.Basic \
  --module Mathlib.Analysis.MeanInequalities \
  --module Mathlib.Analysis.SpecificLimits.Basic \
  --module Mathlib.Data.Real.Sqrt \
  --module Mathlib.Analysis.SpecialFunctions.BinaryEntropy \
  --out /tmp/mathlib-slice.json
pnpm prooflens coverage /tmp/mathlib-slice.json --format markdown
```

## How the number moved

The sweep is not a scoreboard, it is a work queue. Each round below is the same
679 declarations, re-measured after implementing whatever the previous round's
backlog ranked highest. Nothing here was guessed at: every change was made
because the data said those constants were the ones mathematicians actually
write.

| | Round 0 | Round 1 | Round 2 |
|---|---:|---:|---:|
| Structurally classified | 516 (76.0%) | 582 (85.7%) | **653 (96.2%)** |
| Fully readable | 230 (33.9%) | 443 (65.2%) | **552 (81.3%)** |
| Classified with opaque subterms | 286 | 139 | 101 |
| Unrecognised shape | 163 | 97 | **26** |

**Round 1** came from the top of the backlog: `Filter.Tendsto` was the single
most common unreadable shape at 44 declarations, so ProofLens gained a `limit`
proposition, a classifier that distinguishes convergence from divergence, and a
`limit-plot` figure. The round also fixed a measurement error the report itself
exposed — 208 typeclass instance binders were being counted as mathematical
hypotheses, which both distorted assumption sensitivity and filled the opaque
backlog with `IsStrictOrderedRing`.

**Round 2** worked the tail: named properties (`Continuous`, `Summable`,
`CauchySeq`, `IsLUB` …), `StrictMonoOn`/`StrictAntiOn`, conjunctions, set
membership, intervals, coercions and compositions.

A note on `property`. Being readable is not the same as being interpreted:
ProofLens now says "the theorem asserts that `f` is continuous" and stops there.
Recognition requires an explicit entry in the constant table, deliberately — a
blanket rule covering every predicate would make coverage look complete while
the backlog, the thing that tells us what to build next, went quiet.

## What the sweep found about mathlib itself

Assumption sensitivity analysed 437 declarations — those with a proof term and
at least one genuine (non-instance) hypothesis — and found **zero**
stated-but-unused hypotheses. Not one. Across the whole slice, all 770
hypothesis binders occur in their declaration's proof term, later binder types,
or conclusion; so do all 3,296 binders of every kind.

That is not a bug. Mathlib is curated and linted, and Lean's `variable`
mechanism only includes variables a declaration actually mentions, so a stated
but unused hypothesis has to survive both machinery and review to reach the
library.

This is a useful calibration result rather than a disappointing one. It says
assumption sensitivity is not a tool for auditing a mature library — it is a tool
for drafts, for reformalizations, and above all for machine-generated proofs,
where redundant hypotheses accumulate precisely because nothing is grooming them.
ProofLens's own corpus, hand-written, has two.

## Limitations of this measurement

- Seven modules is a slice, not mathlib. It leans toward order theory, real
  analysis and inequalities, which is where ProofLens's classifiers are aimed.
  Coverage over algebra, topology or category theory would be lower.
- "Classified" means ProofLens recognised the statement's shape. It does not
  mean the resulting figure is illuminating.
- Dependency graphs here are single-module: 1,837 dependencies on declarations
  outside the extracted modules are counted, not drawn.
